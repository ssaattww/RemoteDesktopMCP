## Validation and limitations

The link-first repair passed `npm.cmd run check`, `npm.cmd run build`, `npm.cmd run lint:ts`, and `git diff --check`. Its Node 22 MVP command passed 3/3 in 10.882 seconds after correcting the intentional pre-creation missing-config path. The exact source-frozen Node 22 full command, `npx.cmd --yes --package=node@22.23.3 node node_modules/tsx/dist/cli.mjs --test test/**/*.test.ts`, exited 0 with 14/14 passing and 0 failed, cancelled, skipped, or todo in 69.338 seconds. The latest Ubuntu CI candidate confirmed DR003 and ordinary HTTP file operations, but its three `start_search` failures remain open until the newly redacted Desktop Commander detail identifies their cause. These local and partial CI results do not establish matching CI success.

The service remains a local single-PC MVP. Google OIDC, CIMD, refresh token, multi-PC routing, and Funnel publication remain outside this change. `process_start` retains the same-OS-user arbitrary-command trust boundary. `process_kill` delegates only the Desktop Commander session root PID through `force_terminate`; Desktop Commander 0.2.51 does not provide safe descendant identity, so stopping an entire child process tree is not guaranteed. A rejected request remains running and is audited as rejected. A timed-out request becomes `terminating` with `termination_unconfirmed`; it does not start overlapping process operations or restart the Desktop Commander connection. Completion is audited only when Desktop Commander reports it, including an unknown (`null`) exit code. Protected-config identity checks cover the current config and every inode that was successfully private-pin linked; Desktop Commander's own usage tracking can create an unobserved transient version after a tool response, and an alias created outside this service to a version removed before any successful pin cannot be identified safely without reintroducing inode-reuse false positives. That same-OS-user, out-of-file-API race is outside the local MVP isolation boundary.
