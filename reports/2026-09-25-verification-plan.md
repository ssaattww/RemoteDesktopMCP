# 最小版の受入確認

## 対象と証拠

設計の開始点は `320ddb6d5b3a1c54fb4d760612bf4cec4464c5bd`。
この文書は試験の予定であり、成功した証拠ではない。実行結果は実装報告とレビューに記録する。
既存ユーザーの Desktop Commander 設定を変更せず、試験ごとの一時領域を使う。

## 必須確認

| 項目 | 再現する操作 | 合格条件 |
| --- | --- | --- |
| 認証 | 未認証、署名不正、期限切れ、別 audience、scope 不正、許可外ユーザー | ファイルやプロセスの操作前に拒否 |
| OAuth | client 登録、完全一致 redirect、PKCE 付き認可、code の再利用 | 正しい要求だけ token を取得、code は一度だけ使用 |
| 待受け | ローカル起動 | `127.0.0.1` のみ、旧 download URL は利用不可 |
| セッション | 開始、一覧、終了、期限切れ、別所有者 | 有効な所有セッションだけ実操作を受け付ける |
| ノード | 既知 ID、省略、不明 ID | 単一ノードとして一意に決まり、不明 ID は拒否 |
| ファイル | 名前検索、内容検索、読取、部分編集 | 固定版 Desktop Commander に委譲される |
| パス | 範囲外、シンボリックリンク、保護設定への到達 | 正規の操作を維持しながら範囲外アクセスを拒否 |
| プロセス | テスト用短時間コマンド、標準出力と標準エラー、終了・停止 | 論理 ID と実 PID が対応し、統合出力と観測した終了状態を返す |
| DR-001 / High | begin 後に元ファイルを同サイズ・同更新時刻で変更、またはパスを置換 | 返却全チャンクが begin の固定複製の hash と一致 |
| DR-002 / Medium | upload begin 後に別処理が同名ファイルを作る | no-overwrite commit が失敗し、競合ファイルを保持、一時ファイルを清掃 |
| DR-003 / Medium | 設定親ディレクトリを含む、またはその配下を検索 root にする | 構成を拒否し、Desktop Commander へ検索を送らない |
| 転送入力 | 順番違い、並行要求、不正 base64、サイズ・hash 不一致 | 転送先を壊さず拒否、必要な一時領域を清掃 |
| 転送終了 | 完了、中断、セッション終了、期限切れ | 一時ファイル・複製が残らず、終了 ID は再利用できない |
| 監査 | 成功・拒否・失敗・プロセス終了 | 必要なイベントが記録され、password/token/file bytes は記録しない |

## 実行段階

1. 実装担当が限定した回帰試験と型検査を行う。
2. 実 HTTP MCP 経路と固定版 Desktop Commander の組合せを一時環境で実行する。
3. 通常レビューで指摘を修正し、影響する検証を再実行する。
4. 最終候補コミットで lint、check、build、test、差分検査を揃える。
5. 独立レビュー後の報告専用コミットと、レビュー済み実装コミットを区別する。

Google、ChatGPT、Funnel、遠隔ノードの実接続はこのローカル最小版の合格結果には含めない。
依存パッケージの audit 結果も実行時に記録し、ローカル動作テストの結果と混同しない。
