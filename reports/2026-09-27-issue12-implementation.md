# Issue #12 実装と検証

## 変更

使用者の画面 `/user` に、本人の接続、操作履歴、実行中の処理、全実行停止と再開を追加した。
管理者の画面から通常の操作履歴を移し、管理者と使用者の認証・認可を分離した。
検証済み主体ごとに停止状態を保存し、再起動、新規接続、古い待機要求による停止の回避を防ぐ。
再開は本人の画面から行い、以前の接続は復活させない。

Windows の起動処理は Job Object に所属させ、親が先に終了しても子孫の所有関係を維持する。
専用バックエンド経路で所有者を照合して停止する。所有確認に失敗した PID を無条件に終了しない。
停止中は終了要求を再試行できる。

Issue #10 の事後レビューで指摘されたカスタム起動時の設定分離も修正した。
対応する起動経路には専用 bootstrap を使用し、対応できないカスタム起動は拒否する。

## レビュー

実装は GPT-5.6 Terra high と GPT-6 Luna high、レビューは GPT-6 Sol high が担当した。
停止・再開の永続化失敗、非同期待機後の停止世代確認、起動応答前の停止、
PID 再利用時の所有確認、別主体のプロセス操作、認証と CSRF、履歴の主体分離を確認し、指摘を修正した。

## 保証範囲

- 既に行われたファイル変更や外部サービスへの作用は取り消さない。
- 停止前にバックエンドへ送信済みのファイル編集は、停止後に完了する場合がある。`file_patch` は結果を停止通知に置き換えるが、送信済みの編集自体を中断しない。
- Windows 以外では管理対象の根プロセスへ終了要求を送るが、子孫全体の終了は保証しない。
- 任意コマンドは既存の OS ユーザー権限で実行される。OS サンドボックスや権限分離ではない。
- 終了要求への応答喪失や終了失敗は未確認として扱い、プロセス終了と同一視しない。
- 保存装置へ一切書き込めない場合、実行受付は遮断するが、再起動後の停止保存は保証できない。
- 単一サーバープロセスを対象とする。複数サーバー間の停止状態共有は対象外。

## 検証

型検査、Lint、ビルド、および停止・認証・所有管理の個別テストを実行した。
Windows ローカルの Node.js 22.23.3 による全体テストは 74 件中 73 件成功、1 件対象外、失敗なしだった。
この実行後に追加した Windows バックエンド統合テストは単独で成功した。
固定版 Desktop Commander を使用し、親の先行終了後も子孫が存続すること、本人の停止で子孫が終了すること、別主体の処理が継続することを確認した。
停止未確認の画面表示を含む個別テスト 13 件が成功した。
最終レビューと PR の CI 結果は完了時に追記する。
運用中サーバーの再起動や配備は本作業では行っていない。
