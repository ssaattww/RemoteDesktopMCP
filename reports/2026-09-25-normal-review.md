### Required findings

**RDMCP-DR-003 — Medium — carried finding remains open; protected config reaches search and transfer.** Origin: PR #1 finding, implementation verification at `src/index.ts:158-162,172-173,179-180`; related audit path at `src/index.ts:84`. The design requires rejecting any search range with an alias to the config and excludes that file from file and transfer APIs. `search()` sends the allowed root straight to Desktop Commander's `start_search` without screening hard-link aliases. In a live isolated Desktop Commander fixture, a hard link from the child config into the allowed root was rejected by `file_read` but `content_search` returned the config's content and path. A separate live fixture started an upload, replaced its closed `.upload` temp pathname with a hard link to the config, then called `file_transfer_upload_chunk`; the tool returned success and the config grew by one byte. The upload write uses `writeFile(..., {flag:"a"})` on the pathname after the begin handle was closed, so it writes through the replacement inode. The ready audit event also records `configPath` despite the design's audit exclusion. Impact: a protected file is exposed through search and can be modified by a transfer API; the protected path is present in audit. Required action: reject aliases before search or enforce an equivalent non-traversing search boundary, hold and verify an upload temp file identity/handle through writes and commit, avoid logging the config path, and add composed hard-link/search and temp-swap fixtures. The deliberate same-OS-user arbitrary-command trust model is unchanged; this finding concerns the promised file/transfer API boundary. No severity reclassification is made.

**RDMCP-NR-001 — High — required Node 22 test gate fails.** Origin: introduced by implementation/test integration; location `.github/workflows/lint.yml` Windows/Ubuntu jobs, `package.json` test script, `test/mvp.test.ts:40-60`. **RDMCP-NR-002 — Medium — expired transfers can be revived and temporary files persist.** Origin: introduced by implementation; location `src/index.ts:128-133,154-156,177-183`. Expiry only runs when a session is used or listed, with no timer/sweep; it queues cleanup asynchronously under the transfer lock. `transfer()` calls `session()`, then updates `item.touched` and returns the item before the queued expiry check executes. A focused frozen-build reproduction set an active transfer's `touched` to 31 minutes ago, called `transfer()`, and observed `returned:"tid", state:"active", touchedFresh:true` after the queued check. A session that expires is removed without cancelling its transfers. Download-copy and upload-commit pre-`try` errors can also leave untracked or active temp artifacts, while terminal entries remain in the map. Impact: the 30-minute expiry and cleanup contract does not hold; stale transfers can continue and files can remain indefinitely. Required action: expire and clean under the same lock before touching/using a transfer, sweep idle and orphaned artifacts independently of later requests, clean on session expiry and all failed begin/commit paths, and test timeout, session expiry, cancel, failure and restart cleanup.

**RDMCP-NR-003 — Medium — file and content search can return incomplete results as final output.** Origin: introduced by implementation; location `src/index.ts:158-162,172-173`. Desktop Commander's `start_search` launches ripgrep asynchronously, and `get_more_search_results` can report `IN PROGRESS` and `More results available`. The wrapper calls it once at offset 0 and immediately calls `stop_search`, while returning only that first output; the external caller receives no usable continuation ID. The live config-alias fixture produced exactly this `IN PROGRESS` / `More results available` response before the wrapper stopped the session. A larger or slower tree therefore loses later matches. Also, `content_search` promises string search but omits Desktop Commander's `literalSearch: true`, so regex metacharacters change meaning or can fail. Impact: ordinary filename/content search can miss permitted files and cannot reliably search literal strings. Required action: wait/page until completion or expose a safe continuation protocol, preserve bounded result limits, choose literal content semantics, and test delayed/multi-page and metacharacter cases.

**RDMCP-NR-004 — Medium — process output and termination audit are incomplete.** Origin: introduced by implementation; location `src/index.ts:184-190`. `observe()` requests `read_process_output` with `offset:0,length:1000`. In Desktop Commander 0.2.51 those are line-pagination parameters: the response can contain `remaining` lines, and a completed process's `offset:0` always reads its first 1000 retained lines. The wrapper parses an exit marker, sets the logical process to `finished`, and thereafter returns cached output without retrieving the remainder. Thus output beyond the first page is inaccessible through `process_output`. `process_kill` sets `finished` without recording an observed exit code/result; neither natural completion nor kill emits the required `process.exit` audit event. The short marker test does not cover pagination or kill. Impact: users lose output and the audit trail misses the required termination result. Required action: page DC output to the requested/available end with a stable cursor, preserve completion state and exit code, record termination audit for both paths, and exercise >1000 lines and kill in live-DC tests.

**RDMCP-NR-005 — Medium — local OAuth accepts malformed PKCE and unvalidated authorization parameters.** Origin: introduced by implementation; location `src/index.ts:208-239`. `/authorize` accepts any nonempty `code_challenge` and ignores a requested `scope`; `/token` accepts any nonempty `code_verifier` and does not compare a supplied `redirect_uri` with the authorization request. The current live test uses `a-verifier`, a short low-entropy value, confirming this weak path is part of the accepted fixture. [RFC 7636](https://www.rfc-editor.org/rfc/rfc7636.html) defines 43–128 unreserved characters for verifier and challenge; [RFC 6749](https://www.rfc-editor.org/rfc/rfc6749.html) requires the token redirect URI to equal the one in the authorization request and defines `invalid_scope`. Impact: the advertised PKCE S256 authorization-code contract and the verification plan's invalid-scope/redirect cases are not enforced. Required action: validate PKCE challenge/verifier syntax and length, require the registered exact redirect URI at the token exchange, reject unsupported scope at authorization, and add negative HTTP tests. This concerns the local password OAuth flow; Google OIDC and public-client policy remain in P4.

**RDMCP-NR-006 — Low — session list omits specified expiry and state.** Origin: introduced by implementation; location `src/index.ts:17,168-170`. Functional requirements say a session retains creation, last-use, expiry and state, and `session_list` returns expiry. The model stores only `created`/`touched`, and the list returns only `session_id`, `created_at` and `last_used_at`. Impact: clients cannot tell when a session will expire from the documented API. Required action: expose the effective expiry (and store/derive the required state) and test it across activity and expiration.
