# 機能要件

## 目的

RemoteDesktopMCP は、あらかじめ許可した1人のユーザーが、リモートから対象PCのファイル操作とプロセス操作を行うための MCP サーバーとする。
ファイル操作とプロセス操作そのものは再実装せず、各実行ノードで `@wonderwhy-er/desktop-commander` が提供する MCP ツールを呼び出す。
初期版では必要最小限の機能に限定する。

最初の稼働可能な段階は、1台のPCが統括ノードと実行ノードを兼任するローカル構成である。
この段階では既存のパスワード認証を開発用に利用し、Tailscale Funnel からの公開は行わない。
次に Google OIDC を含む公開認証を実装し、ChatGPT からこの1台のPCを操作する。
複数PC接続は、その後に実装する初期版全体の要件として残す。

## 認証

- OAuth/OIDC によりリモート接続ユーザーを認証する。
- あらかじめ登録された1ユーザーだけアクセスを許可する。
- 登録ユーザー以外からのアクセスは拒否する。
- 許可ユーザー設定は対象PC上のローカル設定として管理する。
- 許可ユーザー設定を変更する専用の MCP ツールや HTTP API は提供しない。
- `process_start` は任意コマンドを OS ユーザー権限で実行できるため、その OS ユーザーが設定ファイルを書き換えられる場合は、許可ユーザーもコマンド経由で同じ操作が可能である。

## セッション管理

RemoteDesktopMCP のセッションは、同じユーザーが行う一連の操作を管理するためのものである。
MCP の通信セッションや HTTP 接続とは別に管理する。

### 開始と継続

認証済みユーザーが `session_open` を実行すると、暗号学的乱数を使って一意な `session_id` を生成する。
ファイル操作とプロセス操作では、この有効な `session_id` を必ず指定する。
HTTP 接続、接続元、アクセストークンからセッションを自動判定しない。

認証済みユーザーが同じで有効期限内なら、別の HTTP 接続からも同じ `session_id` を継続利用できる。
`session_list` は有効なセッションだけを返す。
各セッションには、`session_id`、作成時刻、最終操作時刻、有効期限、状態を保持する。
一覧では、このうち `session_id`、作成時刻、最終操作時刻、有効期限を返す。

### 有効期限と終了

有効なセッションで操作を受け付けるたびに、最終操作時刻を更新する。
最後に操作を受け付けてから24時間経過すると、そのセッションは期限切れになる。
`session_close` による明示的な終了も可能とする。
終了済み、期限切れ、またはサーバー再起動前の `session_id` は再利用しない。

### 起動したプロセスとの関係

プロセスを起動したら、起動時の `session_id` と関連付けて監査ログへ記録する。
セッションが終了または期限切れになっても、それだけを理由にプロセスを自動停止しない。
同じユーザーが別の有効なセッションを開けば、論理プロセスIDを指定して状態確認、出力取得、停止を行える。

## Desktop Commander の利用方針

### RemoteDesktopMCP と Desktop Commander の分担

RemoteDesktopMCP は、ユーザーの認証・認可、セッション管理、ノード間認証、操作対象の選択、監査を担当する。
外部公開するツールと引数を制限し、複数PC間で一意なIDも管理する。

実際のファイル操作とプロセス操作は、各PC上の Desktop Commander が担当する。
RemoteDesktopMCP 側で同じファイル探索、読み書き、部分編集、プロセス起動、出力取得、停止処理を重複して実装しない。

### 呼び出しの流れ

1. 各実行ノードで `@wonderwhy-er/desktop-commander` を `stdio` MCP サーバーとして起動または接続する。
2. 起動時に `listTools()` で利用可能なツールと入力定義を確認する。必須ツールがない操作は利用不可とし、独自実装へ切り替えない。
3. `file_*` または `process_*` のリクエストを受けたら、ユーザーの認可、`session_id`、`node_id`、監査、各PCの操作制限を確認する。
4. 確認が済んだら、対応する Desktop Commander ツールを `callTool()` で呼び出す。

### 公開範囲と設定の制限

Desktop Commander 側の設定と RemoteDesktopMCP 側の操作制限の両方を満たすリクエストだけを実行する。
Desktop Commander の管理用ツールや、初期版で許可していないツールは外部へ公開しない。
RemoteDesktopMCP から Desktop Commander の設定を変更する専用機能も提供しない。

Desktop Commander のサーバー設定ファイルは、RemoteDesktopMCP の管理対象外とする。
各実行ノードは、その設定ファイルの実体パスをローカル設定として保持する。
設定ファイルの親ディレクトリと、RemoteDesktopMCP および Desktop Commander の
検索許可ディレクトリが、実体パスで親子関係にある構成は起動時に拒否する。
設定ファイルを検索させた後で結果だけを隠す方式は認めない。
`file_search`、`content_search`、`file_read`、`file_patch`、`file_transfer_*` では、
設定ファイルの実体を検索結果、読み取り対象、変更対象、転送元、転送先に含めない。
検索以外の操作でも、許可ディレクトリ内に見える設定ファイルへの直接指定は拒否する。

この除外は RemoteDesktopMCP のファイル操作 API に対する保護である。
`process_start` は同じ OS ユーザー権限で任意コマンドを実行できるため、
コマンド経由の設定ファイルアクセスまで隔離するものではない。
初期版では、そのための追加の実行隔離機構や別 OS ユーザーを必須にしない。

将来、Desktop Commander にないローカル操作が必要になった場合は、既存ツールで代替できないことを確認する。
そのうえで、独自実装が必要な理由と責任範囲を設計書へ明記してから実装する。

### プロセス実行の権限モデル

初期版では、Desktop Commander と `process_start` から起動するプロセスを、
RemoteDesktopMCP を起動した OS ユーザーと同じ権限で実行してよい。

認証済みの許可ユーザーは、`process_start` を通して
その OS ユーザーが実行できるコマンドやアクセスできるファイルを操作できるものとして扱う。
これは初期版で意図した権限モデルであり、RemoteDesktopMCP は任意コマンドに対する
追加の実行隔離機構を提供しない。

`file_search`、`content_search`、`file_read`、`file_patch` の
許可ディレクトリは、それらのファイル操作ツールの操作範囲を制限するための設定である。
`process_start` から起動した任意コマンドのファイルアクセスを制限するものではない。

そのため、RemoteDesktopMCP を起動する OS ユーザーが読み書きできる設定やファイルは、
`process_start` から起動したコマンドからも到達できる可能性がある。
この権限を許可ユーザーへ与えられない環境では、運用者が RemoteDesktopMCP 自体を
より権限の小さい OS ユーザーで起動する。

別 OS ユーザー、OS のアクセス権による追加隔離などを導入してもよいが、
初期版の必須条件にはしない。
追加隔離を導入していないことだけを理由に `process_start` を利用不可にはしない。

## ファイル操作

- ファイル名およびパスからファイルを検索できること。
- ファイル内容から文字列を検索できること。
- テキストファイルの内容を読み取れること。
- ファイルへ部分的な変更（パッチ）を適用できること。

初期版で公開するツール:

- `file_search`
- `content_search`
- `file_read`
- `file_patch`

## ファイル転送

RemoteDesktopMCP は、ChatGPT と対象PCの間でファイルを双方向に転送できること。
Desktop Commander 自体には汎用バイナリ転送を追加せず、転送は RemoteDesktopMCP の機能として提供する。

初期版では、既存の MCP 接続上でファイル本体を分割して送受信する。
外部の一時URLや追加の公開ポートを必須にせず、Tailscale Funnel 経由で確立済みの MCP 接続だけで完結できるようにする。

転送開始時に一意な `transfer_id` を発行し、ファイル名、サイズ、SHA-256、対象 `node_id`、転送方向を管理する。
ファイル本体は一定サイズのチャンクに分割し、MCP ツールの引数または結果では base64 で表現する。

ダウンロードでは、開始時に作成して固定した一時複製からサイズとSHA-256を算出し、全チャンクを同じ複製から読む。
送信した全バイト列のSHA-256が開始時の値と一致した場合だけ完了とする。
アップロードでは、転送先と同じディレクトリの一時ファイルへ書き込み、全チャンク受信後にサイズとSHA-256を確認してから確定する。
上書き不可の場合は、開始後に別の処理が転送先を作成していても、確定時に原子的に既存ファイルを保護して失敗する。
既存ファイルの上書きは明示指定された場合だけ許可する。

ファイル転送でも各実行ノードの許可ディレクトリを適用する。
Desktop Commander のサーバー設定ファイルは転送元・転送先のどちらにも指定できない。

初期版で公開する転送ツール:

- `file_transfer_download_begin`
- `file_transfer_download_chunk`
- `file_transfer_upload_begin`
- `file_transfer_upload_chunk`
- `file_transfer_upload_commit`
- `file_transfer_status`
- `file_transfer_cancel`

## プロセス操作

- コマンドまたはプログラムを起動できること。
- 起動したプロセスの実行状態を取得できること。
- 起動したプロセスの出力を、Desktop Commander が保持する1つの統合出力として取得できること。初期版では stdout と stderr を別々には返さず、Desktop Commander から判別できない区分を推測して付けないこと。
- 起動したプロセスを停止できること。
- プロセスの終了コードを取得できること。

初期版で公開するツール:

- `process_start`
- `process_status`
- `process_output`
- `process_kill`

## ログ

- MCP 経由で行われた操作を記録すること。
- 認証成功および認証拒否を記録すること。
- セッションの開始と、そのセッションで行われた操作を記録すること。
- プロセス起動時にコマンド、PID、セッションを記録すること。
- プロセス終了時に終了結果を記録すること。
- 操作の成功・拒否・失敗を記録すること。
- 監査ログの取得やログ設定の変更は MCP ツールとして公開しない。

### 管理者向け監査情報の表示

監査ログは対象PC上の管理者向け HTTP 画面から閲覧できる。MCP の許可ユーザー設定とは独立して管理者を設定し、`ADMIN_USERS` にメールアドレスまたは Google の `sub` を `,` で区切って登録する。Google OIDC が設定されている場合は Google ログインを使用し、それ以外ではローカルのメールアドレスとパスワードでログインする。どちらの場合も、設定済み管理者であることを確認する。Google の場合はアカウントの `sub` と公開認証側の許可状態を確認する。

管理者セッションは専用の認証情報で管理し、有効期間は1時間とする。この認証情報には利用者側の処理から読めない属性を付ける。ログインとログイン終了の送信要求は `BASE_URL` から決まる生成元情報と完全一致する送信元ヘッダーのみ受け付ける。ヘッダーが欠落または一致しない場合は拒否する。`ADMIN_USERS` は起動時に読み込むため、変更を反映するにはサーバー再起動が必要である。Google OIDC の公開認証側の許可状態は各リクエストで再確認する。ログイン試行にはレート制限を適用する。管理者用画面と JSON 一覧 API は認証必須とし、応答を保存させない。未認証の画面要求はログイン画面へ転送し、未認証の一覧 JSON API は `401` を返す。ログイン終了ではサーバー側の状態を破棄する。

監査ログは `DATA_DIR/audit.jsonl` に保存する。監査ファイルから復元する履歴は最大500セッションとし、各セッションの直近200記録を保持する。これに稼働中のセッションを追加して一覧を構成するため、表示件数は500を超える場合がある。プロセス起動時のコマンド記録が表示履歴から外れた場合も、直近の関連出力・終了記録に紐付くコマンドは表示できる範囲で補う。出力は記録時に既知の設定済み認証情報と対応済み秘匿条件を秘匿し、各記録につき先頭4,000文字まで保存する。この処理で任意の秘密情報をすべて検出する保証はなく、対応秘匿条件外の秘密情報が出力に残る場合がある。画面では保存済みの範囲と切り詰めを明示する。履歴上限より古い記録や保存前の出力は復元できない。

一覧には開始時刻、最後にコマンドを開始した時刻、状態を表示する。最後のコマンド時刻がない場合は「未実行」とする。この時刻は最終操作時刻ではない。状態による絞り込み（全件・有効・無効）、開始時刻または最後のコマンド時刻による並べ替え、新しい順・古い順の指定を提供する。各行のセッション欄は詳細表示への案内のみとする。日時は日本時間で表示する。

詳細では記録を時系列で示し、`processId` ごとの起動・出力・終了記録を1つのコマンド実行としてまとめる。開始時刻、終了時刻、コマンド、出力、終了コード、結果を記録に存在する範囲で表示し、累積出力の重複表示を避ける。過去の記録上限により開始記録がない場合は開始情報が欠落していることを示す。サーバー再起動をまたいで状態を復元できないセッションは「再起動前・状態不明」として扱う。

セッション一覧は認証済み画面で5秒ごとに更新する。更新では現在の絞り込みと並べ替えを維持し、選択中の詳細表示への案内を可能な場合は維持する。認証期限切れまたは認証失敗を検出した場合は自動更新を停止して再ログインを案内する。詳細画面は狭い画面でも開始・終了時刻、出力、終了コードを読める配置にする。

### 管理者ログ画面の受け入れ条件

- 未認証の利用者は一覧・詳細要求でログイン画面へ転送され、一覧 JSON API では `401` を受け取る。
- 登録した管理者だけがログインでき、管理者設定から外した利用者は有効な認証情報が残っていてもアクセスできない。
- パスワード方式と Google OIDC 方式で、それぞれ登録済み管理者のログインを確認する。Google ログインでは `state` と専用認証情報の結び付きを検証する。
- 一覧の状態絞り込み、2種類の時刻による昇順・降順、日本時間の表示を確認する。コマンド未実行のセッションは「未実行」と表示する。
- 自動更新後も絞り込みと現在選択中の詳細表示への案内が維持され、認証期限切れ時は更新が停止する。
- 並行プロセスを含む詳細でプロセスごとに記録がまとまり、同じ累積出力が重複表示されない。
- 既知の設定済み認証情報と対応済み秘匿条件の秘匿、4,000文字を超える出力の切り詰め表示、記録上限で開始記録が外れた実行の欠落表示と、保持されている終了記録へのコマンド補完、再起動前の状態不明表示を確認する。表示対象外の古い記録は復元されず、対応秘匿条件外の秘密情報が出力に残る場合がある。

初期版で公開するツール:

- `session_open`
- `session_list`
- `session_close`

## 複数 PC 接続

- 1つの ChatGPT 接続から複数の PC を操作できること。
- 外部へ公開する MCP 接続先は統括ノード1台に集約すること。
- 実行ノードは複数台登録できること。
- 統括ノード自身も実行ノードを兼任できること。
- 各実行ノードは一意な `node_id` を持つこと。
- ファイル操作、ファイル転送、プロセス操作は対象 `node_id` を指定できること。
- 構成に登録された実行ノードが2台以上ある場合は、接続状態にかかわらずファイル操作、ファイル転送開始、プロセス操作で `node_id` を必須とすること。`node_id` がない場合に接続中のノードを自動選択しないこと。
- ノード登録とノード認証設定は各 PC のローカル操作からだけ変更できること。
- 遠隔実行ノードは外部公開せず、tailnet 内の通信経路で統括ノードと接続すること。
- ノード間通信は Tailscale IP だけで待ち受け、LAN IP やグローバル IP では待ち受けないこと。
- 統括ノードと実行ノードの双方で監査ログを残せること。

初期版で公開するノード管理ツール:

- `node_list`

詳細は `multi-pc-architecture.md` を参照する。

## 初期版の対象外

認証設定と許可ユーザー設定は MCP ツールとして公開しない。

## 公開経路

- 外部公開には Tailscale Funnel を使用する。
- 固定グローバル IP を前提としない。
- ルーター／モデムのポートフォワーディングを必要としない。
- 外部 MCP サーバーはループバック (`127.0.0.1`) だけで待ち受ける。
- 外部クライアントは Tailscale Funnel が提供する HTTPS URL から接続する。
- Funnel 自体を認証手段として使わず、RemoteDesktopMCP 自身がすべての MCP リクエストを認証・認可する。
- Funnel の設定変更機能は MCP ツールとして公開しない。

詳細は `tailscale-funnel-architecture.md` を参照する。
