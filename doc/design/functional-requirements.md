# 機能要件

## 目的

RemoteDesktopMCP は、許可された単一ユーザーがリモートから対象 PCのファイル操作およびプロセス操作を行うための MCP サーバーとする。
ローカルのファイル操作およびプロセス操作そのものは再実装せず、各実行ノードで `@wonderwhy-er/desktop-commander` が提供する MCP ツールへ委譲する制御層とする。
初期版では必要最小限の機能に限定する。

## 認証

- OAuth/OIDC によりリモート接続ユーザーを認証する。
- あらかじめ登録された1ユーザーだけアクセスを許可する。
- 登録ユーザー以外からのアクセスは拒否する。
- 許可ユーザーの設定変更は対象 PCのローカル操作からのみ可能とする。
- MCP ツール から許可ユーザーを変更する機能は提供しない。

## セッション管理

- セッションは MCP の通信セッションや HTTP 接続とは独立した RemoteDesktopMCP 独自の操作単位とする。
- 認証済みユーザーが `session_open` を実行したとき、暗号学的乱数から一意な `session_id` を生成する。
- ファイル操作とプロセス操作は有効な `session_id` を必須入力とし、HTTP 接続、接続元、アクセストークンから暗黙に推測しない。
- 同じ `session_id` は別の HTTP 接続から継続利用できるが、現在認証されているユーザーが一致する場合だけ受理する。
- 各セッションに作成時刻、最終活動時刻、失効予定時刻、状態を保持する。
- 有効なセッションを使った操作を受理した時点で最終活動時刻を更新し、最終活動から24時間で失効させる。
- `session_close` で明示的に終了できる。終了、失効、サーバー再起動後の `session_id` は再利用しない。
- `session_list` は有効なセッションだけを列挙し、`session_id`、作成時刻、最終活動時刻、失効予定時刻を返す。
- 起動したプロセスは起動時の `session_id` と関連付けて監査する。セッション終了または失効だけを理由にプロセスを自動停止せず、同じユーザーの別の有効なセッションから論理プロセス識別子を指定して状態取得、出力取得、停止を行えるようにする。

## ローカル操作の再利用境界

- 各実行ノードは、ローカルの `@wonderwhy-er/desktop-commander` を `stdio` MCP サーバーとして起動または接続し、ファイル操作とプロセス操作をその MCP ツールへ委譲する。
- 起動時に `listTools()` で利用可能なツールと入力定義を確認し、実行時は `callTool()` を通して呼び出す。
- RemoteDesktopMCP が公開する `file_*` と `process_*` は、外部認可、`session_id`、`node_id`、監査、ローカル方針を適用した後で `Desktop Commander` のツールへ変換する公開用の委譲層とする。
- RemoteDesktopMCP 自身では、同等のファイル探索、ファイル読書き、部分編集、プロセス起動、出力取得、停止処理を実装しない。
- RemoteDesktopMCP が独自に持つ責務は、外部ユーザー認証・認可、RemoteDesktopMCP セッション、ノード認証と要求振り分け、監査、公開ツールの許可方針、ノードをまたぐ論理識別子の管理とする。
- `Desktop Commander` の管理用ツールや初期版で許可していないツールを、そのまま外部 MCP へ公開しない。
- 必須の `Desktop Commander` ツールが存在しない場合、その操作を利用不可として扱い、RemoteDesktopMCP 独自実装へ自動的に切り替えない。
- `Desktop Commander` 側のローカル設定と RemoteDesktopMCP の方針の両方を満たす要求だけを許可する。RemoteDesktopMCP から `Desktop Commander` のローカル設定を変更する機能は提供しない。
- `Desktop Commander` で提供されないローカル操作を将来追加する場合は、独自実装が必要な理由と責務境界を設計へ追加し、既存ツールで代替できないことを確認してから実装する。

## ファイル操作

- ファイル名およびパスからファイルを検索できること。
- ファイル内容から文字列を検索できること。
- テキストファイルの内容を読み取れること。
- ファイルへ部分的な変更（パッチ）を適用できること。

初期版で公開するツール:

- `file_search`
- `content_search`
- `file_read`
- `file_patch`

## プロセス操作

- コマンドまたはプログラムを起動できること。
- 起動したプロセスの実行状態を取得できること。
- stdout および stderr を取得できること。
- 起動したプロセスを停止できること。
- プロセスの終了コードを取得できること。

初期版で公開するツール:

- `process_start`
- `process_status`
- `process_output`
- `process_kill`

## ログ

- MCP 経由で行われた操作を記録すること。
- 認証成功および認証拒否を記録すること。
- セッションの開始および活動を記録すること。
- プロセス起動時にコマンド、PID、セッションを記録すること。
- プロセス終了時に終了結果を記録すること。
- 操作の成功だけでなく拒否および失敗も記録すること。
- ログ機能およびログ設定変更機能は MCP ツール として公開しない。

## セッション用ツール

初期版で公開するツール:

- `session_open`
- `session_list`
- `session_close`

## 複数 PC 接続

- 1つの ChatGPT 接続から複数の PC を操作できること。
- 外部へ公開する MCP 接続先は統括ノード1台に集約すること。
- 実行ノードは複数台登録できること。
- 統括ノード自身も実行ノードを兼任できること。
- 各実行ノードは一意な `node_id` を持つこと。
- ファイル操作とプロセス操作は対象 `node_id` を指定できること。
- 構成に登録された実行ノードが2台以上ある場合、接続状態にかかわらずファイル操作とプロセス操作の `node_id` を必須とし、対象未指定の操作を推測して実行しないこと。
- ノード登録とノード認証設定は各 PC のローカル操作からだけ変更できること。
- 遠隔実行ノードは公開入口を持たず、Tailscale の私設経路で統括ノードと接続すること。
- ノード間通信用の待ち受けは Tailscale の私設 IP だけに限定し、LAN や公開 IP では待ち受けないこと。
- 統括ノードと実行ノードの双方で監査ログを残せること。

初期版で公開するノード管理ツール:

- `node_list`

詳細は `multi-pc-architecture.md` を参照する。

## 初期版の対象外

認証設定および許可ユーザー設定は MCP ツール として公開しない。

## 公開経路

- 外部公開には Tailscale Funnel を使用する。
- 固定グローバル IP を前提としない。
- ルーター／モデムのポートフォワーディングを必要としない。
- 外部 MCP 用の待ち受けはループバック (`127.0.0.1`) のみにバインドする。
- 外部クライアントは Tailscale Funnel が提供する HTTPS URL から接続する。
- Funnel は認証境界として扱わず、RemoteDesktopMCP 自身が全 MCP 要求を認証・認可する。
- Funnel の設定変更機能は MCP ツール として公開しない。

詳細は `tailscale-funnel-architecture.md` を参照する。
