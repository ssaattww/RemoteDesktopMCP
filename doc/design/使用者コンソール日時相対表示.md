# 使用者向け画面のセッション日時を相対表示する設計

## 目的

セッション一覧の作成日時と最終アクセス日時を短い相対表記にし、一覧を離れず正確な日時を確認できるようにする。列幅を抑え、狭い画面での見切れを減らす。

## 対象と境界

対象は使用者向け一覧の「作成日時」「最終アクセス日時」の二列。日時の元データ、並び順、絞り込み、詳細画面への移動先、本人だけを表示する条件、接続状態の更新方法は変えない。詳細画面や操作履歴・稼働状況の日時、セッション情報の編集は対象外とする。

サーバーは既存の `ISO 8601` 日時を返し続ける。日時の生成、保存、通信形式は変更しない。正確な日時は既存契約と同じ日本語・`Asia/Tokyo`・`JST` とする。端末の時刻帯へ切り替えない。

## 現状の根拠

- `src/user-console.ts` の `jst` が正確な日時を日本語の `Asia/Tokyo` で整形し、`JST` を付ける。一覧と詳細画面がこの表示を使う。
- `src/user-console-client.ts` の `timeText` も同じ時刻帯を使う。`refreshState` は `/api/console-state` の応答から `session-rows` を再生成する。ログ再同期後などにも状態更新が呼ばれるため、一覧の行と日時要素は置き換わり得る。
- 相対表記専用の定期処理はない。画面全体を再読み込みせず、初回サーバー描画とクライアント更新を併用する。
- `test/user-console.test.ts` は一覧と詳細画面の日時、本人限定表示、HTML 内の特殊文字を確認する。`test/user-console-client.test.ts` に一覧再生成の試験と簡易な文書構造再現がある。

## 表示と判定規則

作成日時と最終アクセス日時は、それぞれ標準の `details` と `summary` を使う。閉じた状態では相対表記だけを示し、開くと同じ要素内に年・月・日・時・分・秒と `JST` を含む正確な日時を示す。画面上の押す操作だけに限定せず、打鍵のみでも開閉でき、状態は支援技術に伝わる。独自の押す操作やキー操作処理は加えない。

判定順は次のとおりとし、上から最初に当てはまった規則を使う。

1. 入力が欠落、空、時刻帯なし、または解釈不能なら、開閉要素を作らず「—」を表示する。
2. 現在との差の絶対値が60秒未満なら、`JST`日付に関係なく「たった今」とする。
3. それ以外は対象日時と現在日時の`JST`暦日差を求める。差が-1日なら「昨日」、1日なら「明日」、-2日以下なら「N日前」、2日以上なら「N日後」とする。
4. `JST`暦日差が0日の場合は絶対経過時間を使う。60分未満は分、60分以上は時間の数を切り捨て、「N分前／後」または「N時間前／後」とする。

| 境界 | 直前 | ちょうど | 直後 |
| --- | --- | --- | --- |
| 絶対差60秒、日付が同じ | たった今 | 1分前／後 | 1分前／後 |
| 絶対差60秒、`JST`日付が変わる | たった今 | 昨日／明日 | 昨日／明日 |
| 同日の絶対差60分 | 59分前／後 | 1時間前／後 | 1時間前／後 |
| `JST`暦日差1日 | 同日の分・時間表記 | 昨日／明日 | 昨日／明日 |

分・時間は丸めず切り捨てる。日数は`Asia/Tokyo`の暦日差で数え、端末の時刻帯や夏時間に依存させない。`JST`日付差を分・時間より優先し、60秒未満だけをその判定より優先する。最終アクセス日時がない場合は作成日時を使う。

## 共通描画・更新規則

相対表記と正確な`JST`日時は、サーバーとクライアントが同じ日時整形関数を使う。関数は値、現在時刻から相対表記、正規化した日時表現、正確な`JST`日時をまとめて返す。不正値は「—」にする。この関数をクライアント用コードへ同じ関数定義として埋め込み、別の判定実装を作らない。現在時刻を引数で渡せる形にし、境界を固定して試験できるようにする。

サーバー HTML では属性値と表示値を特殊文字の安全な表示に変換する。日時属性には妥当性確認後の正規化文字列を使う。クライアントは要素を `DOM API` で作り、外部値を `textContent` に設定する。外部値を HTML 文字列へ連結しない。

一覧を再生成する前に、セッションIDと日時種別（作成・最終アクセス）ごとの開閉状態を記録する。現在の操作対象が日時の `summary` なら、そのセッションIDと日時種別に対応する再生成後の `summary` を再び操作対象にする。対象が絞り込み後の一覧から消えた場合は、別の要素へ移さない。これにより、開いていた正確な日時と可能な範囲でのキー操作位置を保つ。行順、移動先、絞り込み、本人限定表示を変えない。

経過時間は一覧でだけ自動更新する。一覧がある画面に60秒間隔の処理を一つ設け、相対表記の文字だけを書き換える。正確な日時、要素の種類、開閉状態、操作対象は変更しない。通信要求や行の再生成も行わない。画面離脱時に解除し、ブラウザ保存状態から戻った場合は一つだけ再開する。一覧のない画面では作らない。

相対表記で通常の列幅を抑える。正確な日時を開いた場合は日時欄内で折り返しを許し、一覧の既存の横方向閲覧を保つ。他列の折り返しや表全体の作り直しは行わない。

## 試験駆動開発の計画

製品コードより先に、次の失敗する試験を追加する。

1. **共通関数の境界試験**
   固定した現在時刻で欠落・空・時刻帯なし・不正値、過去と未来、59秒／60秒、同日・日付変更をまたぐ59秒／60秒、59分／60分、昨日・明日・複数暦日を検証する。優先順のため「日付変更をまたぐ59秒」は「たった今」、「同じ差の60秒」は日付差に応じて「昨日／明日」となることを確認する。境界直前・ちょうど・直後の値を検証する。
2. **サーバー描画の回帰試験**
   二列の相対表記、標準要素、開いたときの正確な年月日・時刻・`JST`、欠損時の「—」、悪意ある値の特殊文字処理を確認する。詳細画面の日時、本人限定表示、移動先と絞り込みの既存試験を保つ。
3. **クライアント更新試験**
   初回と状態更新後の相対値・正確な値、作成と最終アクセスの開閉状態、セッション情報、絞り込み、行順を確認する。日時の`summary`をキー操作で選択した状態で再生成したとき、同じ日時の`summary`が操作対象に戻ることも確認する。
4. **定期処理の寿命試験**
   一覧に一つだけ作られ、60秒ごとに相対表記の文字だけが変化することを確認する。通信要求、要素構造、正確な日時、開閉状態、操作対象が変わらないこと、画面離脱で解除され、保存状態からの復帰で二重にならないこと、一覧のない画面では作られないことを確認する。
5. **操作可能性の確認**
   実際のブラウザで日時へ移動し、打鍵だけで開閉できること、正確な日時と時刻帯が支援技術に読まれることを確認する。標準要素の構造検査や単体試験を、実際の支援技術確認の代用としない。

## 文書用語の方針

説明は日本語で書き、一般語を不用意に英語へ置き換えない。必要なコード上の名称、ファイル名、規格名は正確な表記で記す。用語検査を避けるために文章を引用符やコード表記で囲まない。必要語が既存辞書にない場合は、その語と日本語の説明を確認を得てから登録する。この文書では用語一覧を変更しない。

## 変更しないもの

通信形式、日時保存形式、認証・認可、セッションの作成・更新規則、詳細画面の日時、セッション情報の編集、一覧の列・順序・絞り込み、依存関係を変更しない。設計の確認後、試験を先に追加し、製品コードを変更する。
