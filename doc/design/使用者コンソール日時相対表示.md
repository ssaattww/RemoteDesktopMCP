# 使用者向け画面の日時を相対表示する設計

## 目的

セッション一覧の作成日時と最終アクセス日時を短い相対表記にし、必要なときに一覧を離れず正確な日時を確認できるようにする。短い表示で列幅を抑え、狭い画面での見切れを減らす。

## 対象と境界

対象は使用者向け画面のセッション一覧にある「作成日時」「最終アクセス日時」の二列。日時の元データ、並び順、絞り込み、詳細画面への移動先、本人だけを表示する条件、接続状態の更新方法は変えない。詳細画面の日時、操作履歴や稼働状況の日時、移動先やセッション情報の編集は対象外とする。

サーバーは既存の `ISO 8601` 日時をそのまま返す。日時の生成、保存、通信形式は変更しない。正確な日時には既存の日本語・`Asia/Tokyo`・`JST` 表示契約を使い、利用者の端末時刻帯へ切り替えない。

## 現状の根拠

- `src/user-console.ts` の `jst` は正確な日時を日本語の `Asia/Tokyo` で整形し、`JST` を付ける。一覧と詳細画面にこの日時を出力する。
- `src/user-console-client.ts` の `timeText` も同じ時刻帯で整形する。`refreshState` は `/api/console-state` の応答から `session-rows` を作り直し、作成日時と最終アクセス日時を出力する。ログ再同期後などに状態更新が呼ばれるため、一覧の行と日時要素は置き換わり得る。
- 現状、相対時刻更新用定期更新処理はない。画面全体の再読み込みはせず、初回サーバー描画とクライアント更新を併用する。
- `test/user-console.test.ts` は一覧と詳細画面の日時、本人限定表示、HTML 内での特殊文字の安全な表示を検証する。`test/user-console-client.test.ts` には状態更新による一覧再描画の試験と簡易な文書構造再現 がある。

## 表示規則

各日時は、相対時刻を `summary` に持つ標準の `details` 要素とする。開くと、同じ要素内に年・月・日・時・分・秒と `JST` を含む正確な日時を表示する。初期状態は閉じる。ブラウザ標準の操作を使うため、マウスに限定せずキーボードの `Enter` と `Space` でも開閉でき、状態は支援技術に伝わる。独自の画面上の押下だけに限る操作や独自のキー操作処理は追加しない。

| 条件 | 過去 | 未来 |
| --- | --- | --- |
| 時差が60秒未満 | たった今 | たった今 |
| 同じ `JST` 日付で60秒以上、60分未満 | 経過した分数を切り捨てて「N分前」 | 同じ数え方で「N分後」 |
| 同じ `JST` 日付で60分以上、24時間未満 | 経過した時間数を切り捨てて「N時間前」 | 同じ数え方で「N時間後」 |
| `JST` の日付差が1日 | 昨日 | 明日 |
| `JST` の日付差が2日以上 | 「N日前」 | 「N日後」 |

境界は半開区間とし、ちょうど60秒なら1分、60分なら1時間、24時間で日付が異なるなら日単位へ移る。分・時間は丸めず切り捨てる。日数は `Asia/Tokyo` の暦日差で数える。日付差の判定には `JST` の年月日を使い、端末の時刻帯や夏時間の影響を受けないようにする。

日時が欠落、空、時刻帯なし、または解釈不能なら、相対値や開閉操作を作らず「—」を表示する。通常の値は時刻帯付き `ISO 8601` のため、欠損・破損値に対する安全な退避となる。最終アクセス日時がない場合は、現在と同様に作成日時へ代替表示する。

## 描画・更新の設計

サーバー描画とクライアント描画は同じ相対時刻規則と正確な `JST` 整形を使う。時刻表示専用の関数を設け、既存の `timeText` は操作履歴など他の日時用として維持する。現在時刻は引数で渡せる純粋な相対時刻関数にし、境界を固定した試験を可能にする。

サーバー HTML では属性値と表示値を特殊文字の安全な変換する。日時属性には妥当性確認後に正規化した `ISO 8601` 文字列を入れる。クライアントでは要素を `DOM API` で生成し、日時と相対表記は `textContent` に設定する。外部値を HTML 文字列として連結しない。

クライアント更新で一覧を作り直す前に、セッション ID と日時種別（作成・最終アクセス）をキーに各 `details.open` を記録する。行を再生成した後、同じキーの開閉状態を戻す。絞り込み後も応答の順序、移動先、既存列、本人限定データを維持する。行の再作成だけで開いていた正確な日時が閉じないことを確認する。

相対表示は一覧でのみ自動更新する。一覧がある画面に一つだけ60秒間隔の定期更新処理を設け、日時相対表記だけを更新する。通信要求、行の再作成、開閉状態の変更は行わない。画面離脱時に解除し、ブラウザの保存状態から復帰した場合は一つだけ再開する。一覧のない画面では作らない。

短い相対表記で通常の列幅を抑える。正確な日時を開いた場合は日時日時欄内で折り返しを許し、既存の一覧の既存の横方向閲覧を保つ。他列の折り返し、列構成、表全体の幅の再設計は行わない。

## 試験駆動開発の計画

製品コードを変更する前に、次の失敗する試験を追加する。

1. **純粋関数の境界試験**
      固定した現在時刻で欠落・空・時刻帯なし・不正値、過去と未来、59秒と60秒、59分と60分、同じ `JST` 日付から日付境界を越える場合、昨日・明日、複数暦日の表示を検証する。分・時間の切り捨ても境界直前と直後で確認する。
2. **サーバー描画の回帰試験**
      一覧の二列に相対表示と標準 `details`/`summary` があり、開くと年・月・日・時・分・秒および `JST` が読めること、欠損値が「—」になること、悪意ある値が HTML として解釈されないことを確認する。詳細画面の正確な日時、本人限定表示、移動先と絞り込みの既存試験も保つ。
3. **クライアント更新の画面試験**
      初期表示と状態更新後の両方で相対値・正確な値を確認する。作成と最終アクセスの一方または両方を開いた状態で応答を反映し、開閉状態、セッションの詳細画面への移動先、絞り込み、行順が保たれることを確認する。攻撃的なセッション ID、用途、日時文字列が HTML として挿入されないことも確認する。
4. **定期更新処理の寿命試験**
      一覧で定期更新処理が一つだけ作られ、1回の刻みで相対相対表記だけが更新され、通信要求や開閉状態が変わらないことを確認する。離脱で解除され、保存状態からの復帰後も二重登録されないことを確認する。一覧のない画面では作らない。
5. **操作可能性の確認**
      実ブラウザで日時要素へキーボード移動し、`Enter` と `Space` で開閉できること、正確な日時と時刻帯が支援技術に読まれることを確認する。専用ブラウザ依存は増やさず、標準要素の採用と既存の画面回帰試験で担保する。

## 文書用語の方針

通常の説明は日本語で書き、一般語を不用意に英語へ置き換えない。既存コード識別子、ファイル名、規格名は必要箇所だけ正確に記す。用語検査を避けるために文章を引用符やコード表記で囲まない。新しい用語登録が本当に必要な場合に限り、後続実装で最小の用語を日本語の実質的な説明とともに登録する。この設計文書では用語一覧を変更しない。

## 変更しないもの

サーバー API の形、日時保存形式、認証・認可、セッションの作成・更新規則、移動先やセッション情報編集、詳細画面の日時表現、一覧の列・順序・絞り込み、依存関係を変更しない。設計設計確認後、上記の順で試験を先に追加し、製品コードはその後に変更する。
