# 共有Todoの更新履歴

## 目的と範囲

課題 #84 の再実装である。既存の共有Todoと認証境界を保ち、適用された版ごとの本文、状態、親、兄弟順序の変更前後と、その版の全項目を読み取り専用で確認する。更新者は認証された利用者、更新元は MCP または利用者画面として記録する。自然人と機械の区別は推測しない。

旧作業場所の `shared-todo-update-history.md` は読み取り専用の参考資料であり、変更しない。利用者画面の子項目開閉の案内文だけを取り除き、親ごとの折りたたみ・展開機能は維持する。

## 保存と失敗時の契約

既存の `todoLock` 内で版を照合し、`applyTodoChanges` が返す確定配列の変更前後を比較する。一つの要求内の中間状態は表示しない。追加・削除は片側を `null` とし、兄弟の再採番も実際に変わった項目として含める。変更がない要求でも既存契約どおり版は進み、変更一覧は空となる。

既存の非公開 `audit.jsonl` と書き込み処理を使う。`todo.updated` に `history_schema: 1`、変更者、更新元、版、変更前の版、適用日時、全項目、項目ごとの差分を保存する。削除した本文も変更前の値として残る。別の保存場所や依存は追加しない。

既存の適用後に監査記録する順序を保つ。監査保存が失敗しても適用済みの状態は戻さず、`applied: true`、`audit_warning: true`、`history_recorded: false` を返す。書き込み後の確認で失敗する場合もあり、この値は保存成功を確認できなかったことを示す。履歴の完全性を保証しない。次の版と連続しない箇所、現在の版と最新の記録との差、取得範囲の制約を返す。

競合、入力拒否、適用前の失敗は `todo.update_attempt` に分ける。理由は固定された分類だけを保存し、拒否された本文や生の要求、例外の全文を保存しない。認可を通過した対象だけが項目履歴の対象になる。認証や形式の検証で処理に到達しない要求は既存の操作監査に従い、適用版には含めない。試行自体の保存失敗は既存の監査警告の限界として残る。

## 取得範囲と保持

取得は既存監査索引の最新20,000監査記録のうち、本人・対象作業接続に一致する最新50件の履歴記録を返す。成功と失敗の合計が50件で、版と試行は別配列となる。古いものから表示する。分割取得や取得位置の指定は追加しない。全期間の一覧ではなく、取得上限、索引の切り捨て、先頭・末尾の版、版の欠落、現在版との差を明示する。

導入前の変更履歴を合成しない。履歴が空でも変更がなかったとは主張しない。旧形式の監査記録だけから本文を復元しない。画面と MCP の両方で、導入前・保存失敗・取得範囲外の記録が含まれない可能性を明示する。

項目削除後、作業接続の終了・期限切れ後も監査記録が取得範囲にある間は参照できる。再起動時は既存監査読み込みで復元する。ファイルを自動削除する保持期限は既存実装にないが、無期限の参照は保証しない。ファイルの削除・置換・破損、索引の上限により取得できなくなる。監査索引と同じ保持範囲にある成功記録の本人・対象識別子も所有証明に使い、`session.open` だけが範囲外になっても本人の記録を返せる。対象識別子を知るだけでは読めない。

## 読み取り専用の取得と画面

MCP の `todo_history` と認証済み `GET /api/sessions/:sessionId/todo/history` は共通の取得処理を使う。現行Todo取得の稼働中接続制約は変えない。履歴は終了済みも読めるが、現在状態、版、入力途中の本文、鮮度判定時刻、接続の利用時刻、接続寿命、監査ファイルを変更しない。MCP履歴取得は操作監査や鮮度判定を行う更新用の共通処理を通さない。認証はMCP接続または画面の認証済み利用者から導く。

画面は現在の編集領域と独立した履歴領域を持つ。初期HTMLでも最新の記録、全項目、変更前後、別分類の試行、取得範囲を表示する。前後の矢印で隣接版を選び、端では無効にする。版の本文・状態・親・順序・更新者・日時を表示する。現在の版と一致する場合だけ現在版と示す。履歴は静的な表示で編集要素を持たず、値はHTMLを実行せず表示する。

履歴更新操作は読み取りだけを行い、選択済みの版が残る場合は選択を保つ。対象版が取得範囲を外れた場合はその旨を表示し、最新の記録を選ぶ。現在の編集欄、未送信の入力、折りたたみ状態、鮮度判定には触れない。取得失敗時は既存表示を保って失敗を示す。親ごとの折りたたみは現在の編集領域で従来どおり使える。

## 検証

既存の共有Todo設計のテスト駆動開発方針に従い、失敗する試験を先に実行する。追加、編集、状態、移動、親変更、削除、複数変更の確定差分、競合・拒否・失敗、保存警告、所有者境界、終了・期限切れ・再起動、取得上限と欠落、監査と現在状態を変更しない取得を検証する。画面の矢印、端、履歴の安全な表示、現在の入力と版の保持、案内文削除と親別開閉の回帰を検証する。
