# 組み込みツール操作の詳細ログ

## 目的

組み込みツールの操作内容を、`process_start` のコマンドと出力を確認する場合と同じ粒度で使用者画面から追跡できるようにする。
使用者は、何を対象にし、どの範囲を読み、何を変更し、何を転送し、どの結果またはエラーになったかを、操作ごとに確認できること。
既存の操作履歴にある受信時刻、開始時刻、終了時刻、実行時間、ツール、状態、対象概要は維持する。

## 監査ログの契約

操作の受信時と開始時は、現在の軽量なメタデータだけを保存する。
成功、失敗、拒否、取消しの終端記録には、利用可能な場合に `detail` を追加する。
`detail` は画面表示専用の `HTML` ではなく、次の構造化データとする。

```text
detail: {
  version: 1,
  summary: string,
  entries: [
    {
      label: string,
      value: string,
      format: "text" | "diff",
      truncated?: boolean
    }
  ]
}
```

各項目の可変長本文は最大4000文字とし、超過した場合は切り詰めたことを記録する。
既知の認証情報は、既存のコマンド出力と同じ伏せ字処理を通してから保存する。
任意のファイル本文に含まれる秘密情報を完全には判定できないため、詳細ログは既存の使用者ログと同じ本人だけの閲覧範囲に置く。
管理者画面へ通常の操作詳細を追加しない。

ツールごとの詳細生成は一つの定義箇所へまとめる。
引数全体をそのまま監査ログへ保存しない。
将来ツールを追加する場合は、安全に保存できる項目を選ぶ詳細生成定義も同時に追加する。
詳細生成定義がないツールは、既存の対象概要と状態だけを表示し、未知の引数を自動保存しない。

## ツールごとの詳細

### 検索

`file_search` と `content_search` は、基準となる `root_id`、検索文字列、検索結果を保存する。
検索結果が長い場合も本文項目の上限を適用する。
検索失敗時は、入力できた検索条件とエラーを残す。

### ファイル読取

`file_read` は、`root_id`、`relative_path`、`offset`、`length`、実際に返した本文を保存する。
省略された `offset` と `length` は省略されたことが分かる表現にする。
失敗時も、検証前に安全に保存できる要求範囲とエラーを残す。

### ファイル部分変更

`file_patch` は、`root_id`、`relative_path`、期待置換数、変更前後を `diff` 形式で保存する。
差分は要求された `old_string` と `new_string` から生成し、成功時は Desktop Commander の結果も保存する。
失敗時も、実行を試みた差分とエラーを残す。
差分本文にも長さ上限と既知の認証情報の伏せ字処理を適用する。

### ファイル転送

`file_transfer_download_begin` と `file_transfer_upload_begin` は、転送方向、`root_id`、対象パス、サイズ、ハッシュ、転送 ID を保存する。
ダウンロード開始時は作成済みの転送用複製から内容見本を取得する。
アップロード開始時はまだ本文が存在しないため、宣言されたサイズとハッシュを表示する。

`file_transfer_download_chunk` と `file_transfer_upload_chunk` は、転送 ID、開始位置、処理したバイト数、次の位置、完了状態を保存する。
そのチャンクが文字として扱える場合は本文を、そうでない場合は先頭64バイトまでを `hex` 表記した内容見本を保存する。
`Base64` の文字列そのものを内容見本として表示しない。

`file_transfer_upload_commit` は、確定後の対象パス、サイズ、ハッシュと、確定したファイルの内容見本を保存する。
`file_transfer_status` と `file_transfer_cancel` は、転送 ID、方向、状態、位置、サイズなど、転送状態として安全に公開済みの値を保存する。

内容見本は最大4000文字とする。
文字として扱う判定は、有効な `UTF-8` であり、制御文字を含まない場合とする。
それ以外はバイナリとして扱う。
転送用複製や一時ファイルの内部パスは使用者へ表示しない。

## エラーの詳細

終端記録が失敗または拒否の場合は、既存の公開可能なエラー理由に加え、詳細の末尾へ「エラー」項目を追加する。
内部例外のスタックトレースや保護対象の実体パスを新たに公開しない。
停止要求による取消しでは、既存の停止 ID と停止世代を維持し、処理済みの安全な詳細だけを表示する。

## 使用者画面

操作履歴の各行に詳細欄を追加する。
`detail` がある場合だけ `details` 要素を表示し、初期状態は閉じる。
使用者が開いた操作詳細は、同じ操作 ID が差分更新で再描画されても開閉状態を維持する。
本文は `pre` 相当の固定幅表示とし、`HTML` として解釈しない。
`format: "diff"` は差分であることが分かる見出しを付けるが、内容を `HTML` として実行しない。

`process_start`、`process_output`、`process_status`、`process_kill` の既存表示は変更せず、コマンドと出力の詳細領域を引き続き使用する。
操作履歴の詳細は、組み込みツールの監視を補うための領域とする。

## 検証

実装はテストを先に追加し、現行実装で失敗することを確認してから製品コードを変更する。

- 検索条件と検索結果が終端記録へ保存されること。
- ファイル読取の範囲と本文が保存されること。
- ファイル部分変更の差分と結果が保存されること。
- アップロードとダウンロードの対象、サイズ、方向、内容見本が保存されること。
- バイナリ転送は本文を誤って文字として表示せず、限定した `hex` 表記になること。
- 失敗時も安全な入力情報とエラーが表示されること。
- 操作詳細は初期状態で閉じ、差分更新後も使用者が選んだ開閉状態を維持すること。
- 他人の操作詳細は既存の本人確認境界を越えて取得できないこと。
- 詳細本文は長さ上限と既知の認証情報の伏せ字処理を受けること。
- 型検査、許可語方式の設計文書用語検査、文書構文検査、`TypeScript` の `lint`、構築、関連テストと全体テストを実行すること。
