# 長時間実行プロセスの目的とコマンドを確認する設計

## 目的

出力の量や他のプロセスの追加によって表示内容が伸びても、使用者が実行中プロセスの目的とコマンドを確認できるようにする。既存の出力履歴、プロセス単位の対応、本人限定表示を維持する。

## 対象と境界

対象は使用者向けセッション詳細にある `Running operations` と「コマンドと出力の詳細」。実行中プロセスの識別情報、目的、コマンドから出力詳細へ移動できる表示を追加し、プロセス一覧は実行中を終了済みより前に置く。

データ保存形式、監査ログ、認証・認可、所有者判定、コマンドの秘密値除去、既存の秘匿規則、履歴保持件数は変更しない。他の使用者のプロセス情報を新たに取得または表示しない。別利用者の実行、管理者画面、プロセスの制御操作は対象外とする。

## 現状

- `src/user-console.ts` はログイン中の主体に属するセッションだけを詳細表示し、セッション内のプロセス開始・出力・終了記録をプロセスごとにまとめる。
- 各プロセス詳細には目的とコマンド、折り畳み可能な出力、終了結果を表示する。長い出力や継続的な出力の後まで表示が伸びると、目的とコマンドへ戻るには画面内を探す必要がある。
- 実行中の操作は `Running operations` に表示されるが、現在の行には目的やコマンドを確認する移動先がない。
- 履歴順は最後の記録時刻によるため、実行状態を明示した優先順は保証されない。
- `src/user-console-client.ts` は新着ログでプロセス詳細を再構成し、出力の開閉状態をプロセス単位で保つ。

## 表示契約

1. セッション詳細上部の `Running operations` から、現在のプロセスをプロセスID単位で識別できるようにする。本人所有の実行中プロセスについて、目的とコマンドを取得済みの値だけで表示する。
2. 実行中プロセス行に固有の画面内移動手段を置き、該当する「コマンドと出力の詳細」へ移動できるようにする。行と詳細はセッションIDとプロセスIDで対応し、同じIDの別セッションと混同しない。
3. 詳細の先頭には目的、コマンド、状態、出力を同じプロセスの情報として表示する。出力の追加後もプロセスID、目的、コマンド、出力履歴、終了結果を別プロセスへ付け替えない。
4. 一覧と詳細の両方で実行中を終了済みより上に並べる。同じ状態内は既存の新しい記録順を保つ。出力を更新しても実行中の項目は終了済みの項目を追い越されない。
5. 目的またはコマンドがない場合は「未記録」と表示し、他のプロセスやセッションの値を代用しない。空文字列は空のままとせず未記録として扱う。
6. 移動先の識別子や表示文字列を HTML として解釈せず、既存の安全な変換と文字列設定を使う。
7. 画面更新後もセッションIDとプロセスIDを識別に使い、同じ行と詳細を維持する。出力詳細の開閉状態、日時表示や操作対象の保持など既存の画面状態を壊さない。
8. 描画し直す直前にプロセス詳細内の操作対象を調べ、セッションID、プロセスID、要素種別を組み合わせて識別する。更新後も同じ識別子の操作可能要素が存在するときだけ、その新しい要素へ `focus({ preventScroll: true })` を呼び、画面を移動せずに操作位置を戻す。対象が更新後に消えた場合は操作位置を設定せず、別のプロセスへ移さない。実行行から移動したときは、対応するプロセス見出しまたは出力の開閉操作に標準のキー操作位置が置かれることを維持し、出力取得後も同じセッションとプロセスに残す。要素種別は見出しと出力開閉操作を区別する。

## 認可と秘密情報

サーバーは既存の本人認証、セッション所有者、プロセス所有者、操作記録の所有確認を維持する。目的とコマンドは既存の秘匿済み記録からのみ表示し、原文、追加の監査情報、他利用者の状態を参照しない。画面内の移動手段は認可に使わず、既存の本人限定画面内の移動だけに使う。

## 試験駆動開発の計画

製品コードを変える前に試験を追加し、現状の不足を確認する。

1. 複数の実行中プロセスと終了済みプロセスを用意し、一覧・詳細の双方で実行中が先頭に来ること、同じ状態では新しい記録順となることを確認する。
2. `Running operations` の各行に目的とコマンド、正しいセッションIDとプロセスIDへの移動手段があり、目的、コマンド、長い出力がプロセスごとに結び付くことを確認する。
3. 出力追加と状態再描画の後も、目的、コマンド、出力、終了結果の対応、出力詳細の開閉状態、同じプロセス内での操作位置を保つことを確認する。試験用の画面では更新前に見出し、次に出力開閉操作へ実際に `focus()` を行い、再描画後の新しい要素が `document.activeElement` であること、同一のセッションID、プロセスID、要素種別が一致すること、復元呼び出しが `preventScroll: true` であること、`window.scrollY` が変わらないことを個別に検証する。
   - 操作中の詳細が更新後に保持対象から外れた場合、`document.activeElement` が別プロセスの要素にならず、復元用 `focus()` が呼ばれないことを確認する。
   - 2つの異なるセッションで同じプロセスIDを使った試験記録を用意し、一方の見出しまたは出力開閉操作に操作位置を置いて更新する。再描画後に同じセッションID側だけへ戻り、別セッション側へ移らないことを確認する。
4. 目的やコマンドの欠落と空値で未記録を表示し、別プロセス情報を流用しないことを確認する。
5. 他利用者のセッションと操作記録、未所有のプロセスIDを含め、既存の本人限定と所有者境界、秘密値の除去と認可の回帰試験を維持する。
6. `npm test` と既存の TypeScript、文書、用語、製品構築の各検査で変更の整合を確認する。
7. FA780 の Windows 実画面で、以下の安全な標準出力だけを行う手順を実施する。通常の使用者として自身が所有する有効なセッションを開き、別々の目的と識別しやすい出力を使って、1秒ごとに120行を出す実行中プロセスを2つ開始する。例として PowerShell は `1..120 | ForEach-Object { "ISSUE55-A-{0:D3}" -f $_; Start-Sleep -Milliseconds 1000 }` を使い、2つ目は A を B に置き換える。さらに `Write-Output ISSUE55-DONE` のようにすぐ完了する記録を1つ作る。設定済みの安全な実行手段で実施し、既存ファイルを変更・削除する命令や秘密値を含めない。
   - 最初の実行中行が現れた後と、出力が画面領域を越えて積み上がった後に「新着を更新」を実行する。更新後も2つの実行中項目が完了済み項目より上で、目的とコマンドが正しいことを確認する。
   - 各実行中項目の移動操作から該当プロセスへ移動し、その目的、コマンド、同じ A または B の出力を確認する。A と B を交互に更新し、別プロセスの値や操作位置へ移らないことを確認する。
   - 画面記録は、(a) 2件の実行中行と完了済み行の上下関係、(b) A の目的とコマンド、遠くまで続く A 出力、(c) B の目的とコマンド、B 出力を別々に写す。接続情報や認証情報を含めず、主体と画面名、開始・更新時刻、確認結果、失敗時の表示を実施記録に残す。
   - 画面確認後に両方の試験実行が完了したことを確認し、変更提出に画像と実施記録を添付する。Windows 実動作は別の担当が実施し、この変更では実行環境を代替したと主張しない。

## 文書用語

説明文は日本語で記す。実在するコード識別子と実際の画面表示は正確な表記を保つ。用語検査の対象に本書を追加し、辞書の登録語、別名、除外は変更しない。検査回避のために説明を引用符やコード表記で囲まない。

## 変更しないもの

既存のプロセスごとの出力履歴、相対日時表示、セッション編集と日時・詳細開閉・操作対象の保持、プロセス用 API、保存形式、認証・認可、所有者境界、秘密情報除去規則、依存関係を変更しない。
