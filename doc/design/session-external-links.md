# セッション作成時のURL表示

## 目的と範囲

課題45の設計。セッション作成時に任意のURLと表示題名を受け取り、本人の使用者画面で作業先を識別できるようにする。題名・URLの保存契約は課題48の後編集と共有するが、後編集APIや画面は本課題では実装しない。

## 現行実装との接続

- `src/index.ts` の `session_open` は、作業ディレクトリと用途を必須にし、認証済み利用者に所有者付きセッションを割り当てる。セッション本体はプロセス内の `sessions` に保持され、監査記録には `session.open` と作業情報が残る。
- `userOwnsActiveSession` と `userOwnsAuditSession` が稼働中セッションと履歴の所有者を判定する。URLの値も同じ境界を守り、他人のセッションへ返さない。
- `src/user-console.ts` の `/api/console-state` は監査履歴と稼働中セッションをまとめ、`src/user-console-client.ts` が一覧を更新する。URLの値は監査履歴ではなく、本人の稼働中セッションからだけ渡す。
- `src/user-console.ts` と `src/admin.ts` にはHTML特殊文字の置換処理がある。使用者画面は `Content-Security-Policy`、`Referrer-Policy`、`X-Content-Type-Options` も設定する。
- `src/private-storage.ts` は秘密ファイルへのアクセスを制限するが、セッション本体は現在、永続保存されない。URLも新しいファイルや監査記録へ複製せず、稼働中セッションと同じ寿命の一時データとする。
- 任意URLから題名を安全に取得する既存機能はない。標準HTTP/TLS通信機能で取得範囲を限り、新しい依存を加えない。

## 入力と利用者への説明

`session_open` に省略可能な `url` と `title` を加える。作業ディレクトリ、用途、所有者割当、緊急停止中の作成拒否は変えない。

URL欄と題名欄は任意とする。MCPのセッション作成操作と各入力項目に取得動作の説明を付ける。URL欄を含む入力画面がある場合も送信前から次の説明を見える位置に表示する。実行後にだけ表示する説明では不足とする。

> 題名が空欄の場合、入力URLへサーバーから接続して外部文書の題名を取得します。題名を入力すると自動取得は行いません。公開外部文書を指定し、パスワードや秘密値をURLへ入れないでください。

題名を手入力した場合、題名取得用の通信を一切開始しない。題名が空欄で有効なURLがある場合だけ自動取得する。画面とAPIの説明で、URL登録により外部接続が起こり得ることを伝える。取得は画面表示の補助に限り、ログイン済み接続先や非公開のコード変更へ既存認証情報を流用しない。新しい認証許可も求めない。

## URLと題名の形式

- URLは前後の空白を除いた後、最大2,048文字とする。補助文字のUTF-16代替対は分割せず一文字として数える。絶対URLのHTTPまたはHTTPSだけを対象にし、接続先番号はHTTP 80、HTTPS 443に限る。
- URLに利用者名や認証用秘密文字列を含む場合はURL全体を破棄し、取得・保持・表示・記録のいずれにも使わない。別に題名が入力されていれば題名だけを通常文字で表示する。
- 相対URL、壊れたURL、HTTP/HTTPS以外、制御文字、埋め込み空白、許可外の接続先番号は取得やURL案内に使わない。形式不正でもセッション作成は続ける。上限内の不正文字列は本人の稼働中セッション内に限って、URL案内でない文字として保持できる。利用者情報付きURLは表示も保持もしない。
- 上限超過は入力検証エラーとする。空URLは未入力として扱う。URL経路、`query`、`fragment` は入力値として維持するが、`fragment` は通信先へ送らない。`query` に秘密値が含まれる場合があるため、秘密値をURLに入れないよう画面で伝える。
- 手入力題名は前後空白を除き、空なら未入力とする。最大200文字とし、空でない場合は必ず手入力値を優先する。
- 取得題名はHTMLの題名要素から文字だけを取り出し、前後空白を除く。200文字超過、空文字、題名要素なしは取得失敗とする。標準的な文字参照と数値文字参照だけを文字へ置き換え、未知の参照はそのまま残す。取得本文や実行可能な内容は画面へ渡さない。

## 使用者画面の表示

- 有効なURLと題名がある場合は題名全体だけをURL案内として表示し、URL文字列は表示しない。取得前または取得失敗時はURLを表示文字列にした案内を出す。不正URLは案内にせず、題名または無害化したURLを通常文字として表示する。URLも題名もなければ欄を出さない。
- URL表示欄は一覧行の右端に置き、日時、状態、用途、作業ディレクトリ、詳細への移動より目立たない小さな文字と控えめな色にする。狭い画面では折り返す。
- 外部URLは新しい画面で開き、HTML属性には `target="_blank"`、`rel="noopener noreferrer"`、`referrerpolicy="no-referrer"` を設定する。保存値を毎回HTTP/HTTPS URLとして再検査し、HTML本文と属性の両方で特殊文字を置換する。画面への反映でHTML文字列を連結せず、要素を作って `textContent` と検査済み `href` を設定する。
- URLと題名は本人の稼働中セッションからだけ取得する。履歴や他人のセッションには表示しない。セッション終了、期限切れ、サーバー再起動でセッション本体が消えた後はURLも失われる。履歴に残る `session.open` 監査情報へURL、`query`、`fragment`、題名を複製しない。

## 外部外部文書取得の制限

認証済み利用者が入力したURLでも、接続先は信頼しない。標準HTTP/TLS機能で宛先へ直接接続し、環境変数の中継設定、画面側のログイン状態、アプリの認証情報、ローカル資格情報を使わない。送信する情報は固定`User-Agent`、`Accept: text/html`、`Accept-Encoding: identity`、`Connection: close` のみとする。`Cookie`、`Authorization`、`Proxy-Authorization`、`Referer` は送信しない。

### 宛先の検査

1. URLを再解析し、通信方式、DNS名、接続先番号を確認する。利用者情報付き、HTTP/HTTPS以外、許可番号以外は拒否する。
2. IPアドレス表記は直接検査する。DNS名はAと`AAAA`をすべて調べる。単独名、および `.localhost`、`.local`、`.internal`、`.test`、`.invalid`、`.example`、`home.arpa` で終わる名前は拒否する。
3. DNS応答が空、検査不能、または禁止範囲を一つでも含む場合、その名前全体を拒否する。IPv4では次の範囲を拒否する：`0.0.0.0/8`、`10.0.0.0/8`、`100.64.0.0/10`、`127.0.0.0/8`、`169.254.0.0/16`、`172.16.0.0/12`、`192.0.0.0/24`、`192.0.2.0/24`、`192.31.196.0/24`、`192.52.193.0/24`、`192.88.99.0/24`、`192.168.0.0/16`、`192.175.48.0/24`、`198.18.0.0/15`、`198.51.100.0/24`、`203.0.113.0/24`、`224.0.0.0/4`、`240.0.0.0/4`、`255.255.255.255/32`。特殊用途に登録された範囲は一般公開可能な例外も含め拒否する。
4. IPv6は `2000::/3` 内だけを候補とし、`::/128`、`::1/128`、`::ffff:0:0/96`、`64:ff9b::/96`、`64:ff9b:1::/48`、`100::/64`、`100:0:0:1::/64`、`2001::/23`、`2001:db8::/32`、`2002::/16`、`3fff::/20`、`5f00::/16` を拒否する。`fc00::/7`、`fe80::/10`、`ff00::/8` は候補外として拒否する。IPv4を内包するIPv6、領域番号付きIP、解釈が曖昧な表記も拒否する。
5. 接続先を検査済み公開IPに固定し、接続開始時にDNSを引き直さない。HTTPSのTLSのSNIと証明書検査には元のDNS名を使う。複数のDNS応答が混在するときは全体を拒否するため、応答が途中で変わる宛先すり替えにも接続しない。
6. 検査不能、名前解決失敗、検査器例外、接続先不一致は取得失敗として処理する。自DNS名やアプリ待受先を例外許可しない。OS経路や透過中継による転送先まではアプリ内検査で保証できないため、運用側でもサーバーから非公開網への送信を制限する。本課題ではOSや認証設定を変えない。
7. IPv4/IPv6の特殊範囲一覧は[IANA IPv4登録簿](https://www.iana.org/assignments/iana-ipv4-special-registry)と[IPv6登録簿](https://www.iana.org/assignments/iana-ipv6-special-registry)を基準にし、実装時に現行範囲を再確認する。境界は合成データで検査する。

### 応答、転送、上限

- 接続と応答待ちは各3秒、転送を含む全体は8秒を上限とする。題名取得は非同期処理で行い、セッション作成応答を待たせない。同時取得はプロセスあたり最大4件とし、超過分は取得失敗としてURL表示にする。
- HTTP 301、302、303、307、308だけを転送として扱い、最大3回まで追う。相対`Location`は現在URLから解決した後、各転送先で通信方式、接続先番号、利用者情報、DNS応答、全IP範囲、接続先固定を再検査する。HTTPSからHTTPへの格下げは禁止し、検査を続けられない転送は拒否する。
- HTTP成功応答かつ ``Content-Type: text/html``、文字コードUTF-8（省略時もUTF-8扱い）の場合だけ本文を読む。圧縮は要求しない。``Content-Length`` が256 KiBを超える場合は読まず、長さ未指定でも受信累計256 KiBで接続を閉じる。不正UTF-8、HTML以外、その他の応答番号は取得失敗とする。
- 失敗は固定分類だけを内部状態へ記録する。URL、`query`、`fragment`、題名、本文、DNS応答、接続情報を監査履歴、診断記録、エラー文に出さない。取得成功・失敗の監査記録も作らない。

## 保存値と非同期競合

URLと題名は既存のセッション本体と同じく一時データとし、監査記録や別ファイルに保存しない。

| 項目 | 内容 |
| --- | --- |
| `externalUrl` | 上限内の正規化したURL。不正値は本人の稼働中セッション内だけに置ける。利用者情報付きURLは保持しない。 |
| `externalTitle` | 手入力または取得済み題名。空なら未設定。 |
| `externalTitleSource` | `manual` または `fetched`。 |
| `externalTitleStatus` | `pending`、`resolved`、`failed`、`not_requested`。 |
| `linkRevision` | 競合を防ぐ単調増加番号。作成時0。課題48で題名またはURLを変えるたび増やす。 |

手入力題名は `manual` として保存し、取得処理を作らない。URLだけの場合はURLと `pending` をセッションへ設定し、セッションを直ちに作成する。取得処理は開始時のセッションID、所有者、正規化URL、`linkRevision` を記憶する。結果はセッションが稼働中で、所有者・URL・番号が一致し、手入力題名がなく、状態が `pending` の場合だけ反映する。一括反映し、番号を増やす。

題名確定時は監査記録を作らず、本人だけに通知する。画面は所有者認証付きの `/api/console-state` を再取得し、通知にURLや題名を含めない。画面が値を取得するAPI応答にも本人の稼働中セッション分だけを含める。

課題48の後編集では所有者を再確認し、値全体を検証する。題名またはURLを更新したら番号を増やし、以前の取得結果を破棄する。更新時に手入力題名があれば自動取得しない。稼働中の命令が使う作業ディレクトリや後編集APIの実装は本課題に含めない。

## 合成データによる試験計画

失敗する契約試験を先に書き、その後に実装する。DNS、通信先、時刻は差し替え、公開接続先や実ネットワークへ接続しない。内部宛アクセスの攻撃再現や外部宛の負荷試験も行わない。

1. URLなし、題名なし、前後空白、上限境界、上限超過、HTTP/HTTPS、相対URL、壊れたURL、利用者情報、HTTP/HTTPS以外、許可外接続先番号を確認する。不正URLや題名取得失敗でもセッションを作成できる。
2. 手入力題名がある場合に通信が一度も発生せず、題名が空欄の有効URLにだけ非同期取得が始まることを確認する。同時取得数、時間上限、作成応答が取得待ちにならないことも確認する。
3. 合成DNS応答で公開IPv4/IPv6、禁止範囲、自DNS名、非公開網、近距離向け予約、共有用、説明用、複数宛先、予約範囲、混在応答、内部末尾名を検査する。範囲境界の値も与える。
4. 最初は公開IP、次は非公開IPを返す合成DNSで、接続先が検査済み公開IPに固定され、再解決されないことを確認する。実際のネットワーク接続は作らない。
5. 合成転送応答を0〜4回与え、回数上限、相対`Location`、HTTPSからHTTPへの格下げ、別DNS名の再検査、非公開IPへの転送拒否を確認する。各段階で宛先を再検査する。
6. 応答番号、Content-Type、文字コード、`Content-Length`、長さ未指定、256 KiB超過、時間超過、不正UTF-8、題名なし、題名上限を確認する。送信情報に`Cookie`、`Authorization`、`Proxy-Authorization`、`Referer`がないことも差し替え通信機能で確認する。
7. 取得中の手入力題名・URL更新、セッション終了、番号更新を順序制御し、古い結果が値を戻さないことを確認する。
8. &<>、引用符、制御文字を題名とURLに含む表示試料を使い、HTML本文や属性に混入しないことを確認する。題名表示時にURL文字列が本文に出ないこと、右端配置、新しい画面、安全な`rel`属性、不正URLから案内表示を作らないも確かめる。
9. 本人の画面と `/api/console-state` だけがURLを受け取り、他人のセッションには返さないこと、`session.open` と取得失敗の監査履歴・診断記録にURLや題名がないことを確認する。既存のセッション作成、所有者、緊急停止、使用者画面の試験も回帰対象とする。

## 対象外と設計確認事項

- 文書本文、画像、小画像、任意の利用者側プログラム実行、HTMLの自動転送機能、ログイン状態の保存・再利用機構、ログイン必須の接続先は対象外。
- 新しい認証情報や認証許可、OS設定、外部取得用依存、後編集APIは追加しない。
- 特殊用途範囲を広く拒否すること、利用者情報付きURLを破棄すること、題名を本人の稼働中セッションだけに保持すること、題名中の文字参照処理を設計確認する。
- 製品実装は親の設計確認後に開始する。
